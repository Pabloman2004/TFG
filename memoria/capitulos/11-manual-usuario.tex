\chapter{Manual de usuario}
\label{cap:manual}

\section{Requisitos mínimos}

La aplicación es una página web que se ejecuta por completo en el
navegador. No requiere cuenta, ni instalación de cliente, ni un servidor
propio una vez servidos los ficheros estáticos. El profesional necesita:

\begin{itemize}[leftmargin=1.4em,itemsep=0.2em]
  \item Un navegador de escritorio o tableta actual (Chrome, Edge o
  Firefox en su versión vigente) con JavaScript activado.
  \item Resolución de tableta o escritorio. Por encima de 1024\,px el
  diseño muestra dos columnas (captura a la izquierda, criterios a la
  derecha); entre 768 y 1024\,px los resultados pasan debajo; por debajo
  de 768\,px las pestañas de sistema se sustituyen por un selector. El
  uso previsto es consulta en tableta apaisada o en ordenador, no en un
  teléfono de gama estrecha.
  \item Conectividad solo para cargar la página y el catálogo de
  criterios. El caso no se envía a ningún servidor.
\end{itemize}

Para ejecutar o modificar el proyecto en local se requiere, además,
Node.js 20.19 o superior (requisito de Angular 20) y npm. No hace falta
base de datos ni ningún servicio en segundo plano.

\section{Instalación y puesta en marcha}

Desde la raíz del repositorio:

\begin{lstlisting}[numbers=none]
npm install
npx ng serve --host 127.0.0.1 --port 4200
\end{lstlisting}

El servidor de desarrollo queda en \texttt{http://127.0.0.1:4200}. El
navegador abre la pestaña de medicamentos. La configuración de
desarrollo es la predeterminada de \texttt{ng serve}; no se utiliza la
compilación de producción para trabajar.

Otras órdenes útiles:

\begin{itemize}[leftmargin=1.4em,itemsep=0.2em]
  \item Compilación de desarrollo:
  \texttt{npx ng build -{}-configuration development}.
  \item Batería de pruebas, una sola pasada, Chrome sin ventana:
  \texttt{npx ng test -{}-watch=false -{}-browsers=ChromeHeadless}.
\end{itemize}

La persistencia del caso en curso vive en el \texttt{localStorage} del
origen (\texttt{127.0.0.1:4200} en local). Borrar los datos del sitio
equivale a reiniciar el caso.

\section{Guía de uso}

El flujo tiene dos pasos y un panel de resultados siempre visible. No
hay pantalla de datos demográficos ni historial de casos: se seleccionan
medicamentos, se completan diagnósticos y, si procede, las constantes de
la pestaña «Otros»; los avisos STOPP y START se actualizan al vuelo. Las
figuras de esta sección son esquemas de interfaz (wireframes), no
capturas.

El recorrido habitual es: (1)~marcar los fármacos activos; (2)~leer los
avisos que ya puedan dispararse solo con medicación; (3)~pasar a
diagnósticos; (4)~rellenar la analítica en «Otros» cuando un criterio
dependa de TFGe, presión arterial, iones u otras constantes; (5)~exportar
PDF, copiar el texto, guardar el JSON o reiniciar.

\subsection{Pantalla de medicamentos}

La~\cref{fig:wire-meds} resume el primer paso. La cabecera alterna entre
Medicamentos y Diagnósticos y ofrece \emph{Visualización} (orientación
de las pestañas de sistema) y \emph{Exportar PDF}. La barra de herramientas
permite guardar el caso en JSON, cargar uno previo, abrir la guía rápida
y reiniciar ---esta última acción pide confirmación---.

A la izquierda, un raíl de sistemas (Cardiovascular, Neurológico, Renal,
etc., más «Otros») filtra el catálogo. Dentro de cada sistema hay dos
bloques: los grupos propios de esa pestaña y, debajo, los
\emph{relevantes de otros sistemas}, que la aplicación muestra porque
algún criterio de la pestaña activa los cita. Marcar un fármaco en el
bloque foráneo no duplica la selección: el mismo identificador se
comparte entre pestañas. Si el principio activo no está listado, la
opción \emph{Otro} del grupo añade un ítem con la clase farmacológica
del grupo, de modo que los criterios que miran esa clase puedan
disparar.

A la derecha, el panel \emph{Criterios activados} se actualiza al
marcar o desmarcar. Un contador en la barra resume medicaciones y
diagnósticos ya elegidos. Cada pestaña puede marcarse como revisada
cuando no hay selección, para dejar constancia de que se miró y no
aplica nada.

\subsection{Pantalla de diagnósticos y analítica}

La~\cref{fig:wire-dx} muestra el segundo paso, con la misma cabecera y
el mismo panel de criterios. Las pestañas corresponden a sistemas
diagnósticos (Cardiovascular, Neurológico, \ldots). Dentro de cada una
vuelven a aparecer el cubo propio y el de diagnósticos relevantes de
otros sistemas. Algunas familias ---la hipertensión--- se presentan como
opciones excluyentes: marcar «HTA grave» desmarca «HTA moderada».

No hay un paso aparte de datos del paciente. La analítica y las
constantes (TFGe, presión arterial sistólica y diastólica, frecuencia,
QTc, potasio, sodio, calcio corregido, TSH) viven en un panel fijo de la
pestaña \emph{Otros}. El panel no depende de lo que esté marcado: un
START como el de antihipertensivo ante PAS/PAD elevadas se evalúa por la
ausencia de fármaco, y ninguna casilla «activaría» esos campos. Si un
valor no se rellena, los criterios que lo leen no disparan.

\subsection{Resultados y generación del informe}

El panel derecho (\cref{fig:wire-resultados}) es el resultado: no hay
una tercera pantalla. Los avisos START (omisión de tratamiento indicado)
van encima; los STOPP (prescripción potencialmente inapropiada), debajo.
Cada bloque muestra un contador y agrupa las tarjetas por sistema
orgánico, plegables. El texto de cada tarjeta es el \texttt{summary} del
criterio, con umbrales de dosis o duración cuando la guía los menciona
---el profesional juzga si aplican; la interfaz no pide esos datos.

Desde cualquier paso se puede:

\begin{itemize}[leftmargin=1.4em,itemsep=0.2em]
  \item \textbf{Exportar PDF:} informe del caso y de los criterios
  activados, generado en el navegador.
  \item \textbf{Copiar criterios:} texto plano al portapapeles, útil
  para pegarlo en la historia clínica.
  \item \textbf{Guardar / Cargar:} fichero JSON versión 1.0 (medicación,
  diagnósticos, analítica). Un JSON ajeno o de versión distinta se
  rechaza con un mensaje comprensible.
  \item \textbf{Reiniciar:} vacía el caso de \texttt{localStorage} tras
  confirmar.
\end{itemize}

\section{Preguntas frecuentes}

\paragraph{¿Esta herramienta sustituye al juicio clínico?}
No. Es un cribado: señala criterios STOPP/START que \emph{podrían}
aplicar al caso introducido. La decisión de deprescribir, iniciar o
mantener un tratamiento es siempre del profesional, a la luz de la
situación concreta y de la guía~\cite{omahony2023stopp,sacyl2023stopp}.

\paragraph{¿Dónde se guardan los datos?}
En el \texttt{localStorage} del navegador, en el origen desde el que se
sirve la página. No hay servidor de aplicación ni cuenta de usuario. El
contenido no sale del equipo salvo que se exporte un JSON o un PDF.

\paragraph{¿Puedo cargar un caso ya revisado?}
Sí. \emph{Guardar} descarga un JSON v1.0; \emph{Cargar} lo restaura
(medicación, diagnósticos y analítica). El fichero debe ser una
exportación de esta aplicación; un documento arbitrario se rechaza.

\paragraph{¿Y si el fármaco o el diagnóstico no está en el catálogo?}
En el grupo correspondiente se marca \emph{Otro}. El ítem hereda la
clase del grupo (medicamentos) o un código asociado al grupo
(diagnósticos), de forma que los criterios que razonan por clase o por
familia puedan evaluarse. No inventa un principio activo nuevo en el
catálogo maestro.
